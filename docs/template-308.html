Sessions

Accessing the Data Platform to retrieve content requires your application to authenticate and manage connection semantics to keep the user session live. LSEG Data Libraries provide this managed access through an interface called a session. The session is the interface to the data platform and is responsible for defining authentication details, managing connection resources, and implementing the necessary protocol to communicate with the data platform. Depending on the access point your application uses to connect to the platform, it can choose from one of the session implementations to initiate the connection. For the creation phase, all session implementations expose the same API and behave in the same way.

The session types are defined in lseg.data.session.desktop, lseg.data.session.desktopdirect and lseg.data.session.platform. They all extend one common base class, lseg.data.session.Session, which is not created directly: the members listed below are available on every session you create.

Creating a session

lseg.data.session.Definition defines the sessions (either desktop sessions or platform sessions).

Definition(name: str | None = None)
Parameter Type Required Default Description
name str | None No None Name of the session to create. This name must refer to a session and the related parameters defined in the configuration file of the library. For example: platform.my-session

Definition.get_session() creates and returns the session. It returns the instance of the defined session.

import lseg.data as ld

platform_session = ld.session.Definition(name="platform.my-session").get_session()

You can also open a session with ld.open_session(), which opens and returns a session.

Default session

Function Description
ld.session.get_default() -> Session Gets the default session.
ld.session.set_default(session: Session) -> None Set the default session.

set_default takes one parameter, session: the logical session to the data platform.

Methods

These methods are available on every session.

Method Description
open() -> OpenState Opens the session.
async open_async() -> OpenState Opens the session asynchronously.
close() -> OpenState Closes the session.
async close_async() -> OpenState Closes the session asynchronously.
on_state(callback) Registers a defined callback function. Called by the library whenever the state of the session is updated.
on_event(callback) Registers a defined callback function. Called by the library whenever the event of the session is updated.
set_log_level(log_level) Sets the level of log messages. By default, logs are disabled.
get_log_level() Gets the current log level.

open, open_async, close and close_async each return an OpenState; see Session states and events.

on_state and on_event

on_state(callback: Callable[[OpenState, str, Session], None]) -> None
on_event(callback: Callable[[EventCode, dict | str, Session], None]) -> None
Method Parameter Description of the parameter
on_state callback Callback function or method to be notified of any state change.
on_event callback Callback function or method to be notified of any event change.

Both raise TypeError if the user provided an invalid object type.

set_log_level and get_log_level

set_log_level(log_level: int | str) sets the level of log messages. By default, logs are disabled.

Parameter Description
log_level Log level value. Possible values are : [CRITICAL, FATAL, ERROR, WARNING, WARN, INFO, DEBUG, NOTSET]

get_log_level() gets the current log level. It returns an int: the current log level of the session logger.

Properties

Property Description
app_key Returns the application id.
open_state Returns the session state.
